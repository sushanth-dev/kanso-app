# ST-020 Account Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a responsive React account shell that uses the existing Better Auth and account APIs for sign-up, sign-in, sign-out, account display, player maintenance, and guardian attachment.

**Architecture:** Add one Vite workspace under `apps/web`. Generate DTCG outputs and OpenAPI types before gates run, use `openapi-fetch` behind a small account API, and let TanStack Query and code-based TanStack Router own server state and navigation. Browser code stays same-origin through Vite's development proxy, so Better Auth's httpOnly cookie remains the only session mechanism.

**Tech Stack:** Node 24.19, npm workspaces, React 19, Vite, strict TypeScript, Tailwind CSS 4, Style Dictionary, Astryx 0.4, TanStack Router, TanStack Query, Better Auth client, `openapi-typescript`, `openapi-fetch`, Vitest, Testing Library, Playwright, and axe.

## Global constraints

- Work only in `app/feature-st-020-account-shell` on `feature/st-020-account-shell`; do not edit `app/main`.
- Add only the dependencies approved in the design review. Do not add TanStack Table, TanStack Virtual, D3, chess.js, a form library, or a validation library.
- Keep `tokens/*.json` as the source of truth. Generated CSS, TypeScript, JSON, and OpenAPI types stay gitignored.
- Use only semantic Kanso token utilities in components. Do not use primitive token names or hardcoded colors, radii, spacing, typography, shadows, or motion values.
- Use Astryx primitives where they exist. Use native semantic HTML when Astryx has no matching primitive; do not create a wrapper library.
- Use the generated OpenAPI types and `openapi-fetch` for `/me` and `/players*`. Better Auth alone owns `/api/auth/*`.
- Never accept or send an owner field. Player ownership comes only from the session on the API.
- Keep credentials and session tokens out of application state, storage, logs, tests, and rendered output.
- Render API and account strings as React text. Do not add `dangerouslySetInnerHTML` or another raw HTML path.
- Meet WCAG 2.2 AA, including keyboard operation, visible focus, 320 CSS pixel layout, 200 percent text zoom, reduced motion, and non-color status cues.
- Do not add AWS hosting resources or update delivery story/status files before merge.
- Use TDD for each behavior. Every red step must fail for the stated missing behavior before production code is added.

- [ ] **Step 2: Implement the generated account client**

`account-api.ts` exports these exact aliases and operations:

```ts
import createClient from 'openapi-fetch';
import type {components, paths} from '../generated/api.ts';

export type Me = components['schemas']['Me'];
export type Player = components['schemas']['Player'];
export type CreatePlayer = components['schemas']['CreatePlayer'];
export type UpdatePlayer = components['schemas']['UpdatePlayer'];
export type AttachGuardian = components['schemas']['AttachGuardian'];
export type ApiError = components['schemas']['ApiError'];

export class ApiRequestError extends Error {
  constructor(
    public readonly status: number,
    public readonly code: string,
    public readonly issues: ApiError['issues'],
    message: string,
  ) {
    super(message);
    this.name = 'ApiRequestError';
  }
}

function failure(status: number, body: ApiError | undefined): ApiRequestError {
  return new ApiRequestError(status, body?.code ?? 'request_failed', body?.issues, body?.message ?? 'The request failed.');
}

export function createAccountApi(fetcher: typeof globalThis.fetch = globalThis.fetch) {
  const client = createClient<paths>({fetch: fetcher, credentials: 'same-origin'});
  return {
    async getMe(): Promise<Me> {
      const result = await client.GET('/me');
      if (result.data !== undefined) return result.data;
      throw failure(result.response.status, result.error);
    },
    async createPlayer(body: CreatePlayer): Promise<Player> {
      const result = await client.POST('/players', {body});
      if (result.data !== undefined) return result.data;
      throw failure(result.response.status, result.error);
    },
    async updatePlayer(playerId: string, body: UpdatePlayer): Promise<Player> {
      const result = await client.PATCH('/players/{playerId}', {params: {path: {playerId}}, body});
      if (result.data !== undefined) return result.data;
      throw failure(result.response.status, result.error);
    },
    async attachGuardian(playerId: string, body: AttachGuardian): Promise<void> {
      const result = await client.POST('/players/{playerId}/guardians', {params: {path: {playerId}}, body});
      if (result.response.ok) return;
      throw failure(result.response.status, result.error);
    },
  };
}

export type AccountApi = ReturnType<typeof createAccountApi>;
export const accountApi = createAccountApi();
```
